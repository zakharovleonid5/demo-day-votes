# Demo Day Voting

Мобильная страница голосования и кабинет организатора с разделами «Выступления», «Жюри», «События» и «Организаторы».

## Запуск локально

```bash
cd demo_day_voting
$env:ADMIN_LOGIN="admin"
$env:ADMIN_PASSWORD="your-initial-admin-password"
npm start
```

- Голосование: http://localhost:3100/
- Админка: http://localhost:3100/admin

Данные лежат в `data/db.json`. При первом запуске создаётся аккаунт организатора из `ADMIN_LOGIN` и `ADMIN_PASSWORD`; затем он хранится в базе. Изменение переменной окружения не меняет пароль существующего аккаунта. Дополнительные аккаунты создаются в разделе «Организаторы»: имя, логин (короткое имя или почта) и пароль от 10 символов. Telegram-вход в этой версии не подключён.

Пароли хранятся как scrypt-хеши с индивидуальной солью. Сессии действуют сутки и сбрасываются при перезапуске сервера. Отзыв доступа немедленно завершает сессии удалённого организатора. Удалить собственный аккаунт нельзя. Все организаторы имеют одинаковые права.

Кнопка «Сменить пароль» в разделе «Организаторы» доступна для своего аккаунта и коллег. Подтверждение — текущий пароль организатора, выполняющего действие; новый пароль нужно ввести дважды (10–256 символов). После смены все сессии изменённого аккаунта закрываются, кроме текущего браузера при смене собственного пароля: он получает новую сессию. Неверное подтверждение ограничено пятью попытками за 15 минут на аккаунт. Смена пароля работает и после завершения события.

Для продакшена задайте `NODE_ENV=production`, используйте HTTPS reverse proxy и сохранение каталога `data` между деплоями. `HOST` по умолчанию `127.0.0.1`, `PORT` по умолчанию `3100`; альтернативный путь базы задаётся через `DATA_FILE`. Пароль первого аккаунта нужно задать до первоначального запуска. Сервер отдаёт только разрешённые HTML/CSS/JS и шрифты, база и исходники через HTTP недоступны.

При работе через Vercel задайте `PUBLIC_ORIGIN=https://demo-day-votes.vercel.app`. Только этот явно заданный адрес дополнительно разрешён для проверки Origin и генерации QR; произвольным `X-Forwarded-Host` приложение не доверяет.

- Node.js 24, nginx, systemd `demo-day-voting`; приложение работает от непривилегированного пользователя `demo-day` на `127.0.0.1:3100`.
- Код: `/opt/demo-day-voting/current`; база: `/var/lib/demo-day-voting/db.json`; конфигурация: `/etc/demo-day-voting.env` с правами 600.
- Снимки базы: `/var/backups/demo-day-voting`, ежедневно, хранение 30 дней. Это копии на том же VPS: для защиты от удаления сервера нужна отдельная внешняя копия.
- TLS: Let's Encrypt, автоматическое обновление через `certbot.timer`, nginx перезагружается после обновления сертификата. В access log nginx не записываются параметры URL с персональными токенами.
- SSH: вход по ключу; парольный вход выключен после проверки ключа. Локальный ключ хранится вне проекта, в `~/.ssh/demo_day_194_87_103_89`.
- Конфигурация инфраструктуры лежит в `deploy/`. `bootstrap.sh` предназначен для первоначальной установки на пустой VPS; не запускайте его поверх работающего production, поскольку он временно заменяет nginx-конфигурацию. `release.sh` обновляет код, не заменяя уже существующую базу и конфигурацию.
- Пароли, база и локальные файлы `data/production-*` не должны попадать в GitHub. При первом переносе пароль аккаунта `admin` заменён случайным; локальная база не изменяется.

## Голосование и события

- В «Событиях» кнопка «Изменить название и шапку» позволяет задать название голосования (до 300 символов) и текст под заголовком (до 600 символов). Название используется в кабинете и анкете жюри. Пустой текст включает стандартную инструкцию для режима топ-1/топ-3. После завершения события его оформление зафиксировано вместе с результатами. Анкета использует общую типографику и оформление кабинета (`admin.css`) с адаптацией для голосования (`voting.css`).
- Доклады можно добавлять, редактировать, удалять и упорядочивать перетаскиванием или стрелками, в том числе на телефоне. Редактирование названия, спикера и описания сохраняет ID доклада, его порядок и голоса. Завершённые события доступны только для просмотра.
- Режим топ-1: один голос за доклад. Топ-3: 2 балла за первое место, по 1 за второе и третье.
- Второй раунд: топ-6 с ненулевыми баллами; полное равенство на границе включает всех. При равенстве баллов сравниваются первые, затем вторые места. Голоса раундов не смешиваются.
- Жюри получает персональные ссылки; общая ссылка `/vote` сохраняет выбор отдельно для каждого браузера. Старый адрес `/?public=1` также поддерживается. Это не идентификация человека: другой браузер или очищенное хранилище считается новым устройством. Не меняйте домен и браузер во время голосования: хранилища разных адресов независимы.
- `/vote` явно открывает общую анкету, игнорируя старые личные приглашения в памяти браузера. Недействующее личное приглашение не превращается в анонимный голос автоматически; предлагается запросить новое или явно открыть общую анкету. Если браузер запрещает хранение данных, общее голосование блокируется с объяснением, личная ссылка продолжает работать.
- Рядом с общей и каждой персональной ссылкой есть кнопка «QR-код» с просмотром и скачиванием PNG. QR генерируется локально на сервере библиотекой `qrcode`, без внешних сервисов, и содержит адрес сайта, на котором открыт кабинет. Персональный QR даёт доступ от имени конкретного члена жюри: не публикуйте его для всех. QR с адресом localhost не подходит для раздачи на телефоны; создавайте его из кабинета по публичному адресу после публикации.
- В «Событиях» блок «Статистика текущего события» показывает прогресс, лидерборд и матрицу. Лидерборд и матрица в интерфейсе организатора скрыты до голосования всего персонального жюри или завершения события. API организатора возвращает данные для всех раундов; это интерфейсное скрытие, а не запрет организатору получать результаты через API. После сохранения выбора жюри видит текущий топ-3.
- «Завершить событие» закрывает приём голосов и сохраняет неизменяемый снимок программы, жюри и голосов обоих раундов. Повторное завершение не дублирует архив.
- «Создать событие» во вкладке «События» доступно после завершения текущего события. Новый список докладов, новые ссылки жюри и голоса начинаются с нуля; аккаунты организаторов и история сохраняются. Общая ссылка ведёт на текущее событие; старые персональные ссылки не принимают голоса в новом событии.
- В той же вкладке раздел «Завершённые события» позволяет смотреть программу и результаты каждого раунда, включая индивидуальные выборы и комментарии. Плашка статуса и завершение события находятся только здесь. Старые ссылки `#results` и `#history` открывают «События».

## Импорт программы из Excel

Скрипт `import-program.ps1` читает первый лист программы: E — спикер/команда, F — доклад. Направление, зал и часть программы не импортируются. Строки без спикера (открытие, перерыв, закрытие) исключаются. Названия и порядок переносятся из файла без редакторских изменений.

Предпросмотр без изменений:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\import-program.ps1 -Workbook "C:\path\program.xlsx"
```

Импорт через работающий локальный сервер. `-StartNewEvent` завершает текущее событие и сохраняет его в истории перед созданием нового:

```powershell
$env:VOTING_ADMIN_PASSWORD="your-admin-password"
powershell -NoProfile -ExecutionPolicy Bypass -File .\import-program.ps1 -Workbook "C:\path\program.xlsx" -Login admin -Title "Demo Day" -Apply -StartNewEvent
```

Без `-StartNewEvent` импорт разрешён только в пустое открытое событие. Повторный импорт того же файла в текущее событие ничего не меняет. Данные переносятся через защищённый API, без прямой перезаписи открытой базы. В локальное событие 5 октября 2026 загружены 22 доклада из `программа Demo Day.xlsx`; предыдущая программа сохранена в истории.

## Проверки

```powershell
npm ci
npm test
npx playwright install chromium
npm run test:ui
```

Серверные тесты проверяют баллы, финалистов, аккаунты, отзыв доступа, историю и восстановление после перезапуска. Браузерные тесты на компьютере и телефоне используют временные базы, не затрагивая рабочие данные. Отдельной сборки нет: приложение работает на Node.js и статических HTML/CSS/JS. В production зависимости для тестов можно исключить: `npm ci --omit=dev`.

## Оценка сервера

Для 20-100 голосующих достаточно самого маленького VPS:

- 1 vCPU;
- 512 MB RAM, лучше 1 GB RAM с запасом;
- 5-10 GB SSD;
- Node.js 20+;
- HTTPS через nginx/Caddy.

Даже 100 человек, 20 выступлений и 4 критерия дадут примерно 2 000 оценочных строк. JSON-база займет меньше нескольких мегабайт. Основной запас нужен не под данные, а под ОС, Node.js, логи и деплой.
